# O'zgarishlar tarixi (Batch 10, veb)

Kim: `admin`, `direktor`, `super_admin` (audit_log RLS — Batch 1). Tiklash — faqat `admin`, `super_admin`.

## Sahifa `/history` — ikki tab

**Tarix** — `audit_log` yozuvlari, eng yangisi birinchi, 50 tadan sahifalash.
- Filtrlar (`FilterBar`): davr (Batch 9 `periodRange`), jadval (o'zbekcha nomlar: Harakatlar, Xaridlar, Podotchet, Materiallar, Birliklar, Muqobil nomlar, Obyektlar, Foydalanuvchilar, So'rovlar, O'tkazmalar, Inventarizatsiya, Smeta, Ogohlantirishlar, Firma, Kirish), amal (Qo'shildi, O'zgartirildi, O'chirildi, Tiklandi, Login berildi, Telegram bog'landi), kim (profil), qurilma (veb / mobil / tizim), yozuv (`record_id` — "Shu yozuv tarixi" havolasidan).
- Qator (`EntryRow` uslubi): amal belgisi va rangi (qo'shildi — yashil, o'zgartirildi — ko'k, o'chirildi — qizil, tiklandi — to'q ko'k), yozuv nomi ("Sement M400 · 30 qop kirim"), kim, qachon, qurilma belgisi.
- Bosilganda — `DetailSheet`: o'zgargan maydonlar jadvali "Maydon | Oldin | Keyin" (o'zbekcha maydon nomlari, qiymatlar formatlangan: summa, miqdor, sana, holat, bog'langan obyekt/material/odam nomi), "Shu yozuvning butun tarixi" havolasi, o'chirilgan bo'lsa "Tiklash".

**O'chirilganlar** — barcha jadvallardagi soft delete qilingan yozuvlar (davr, jadval filtri): nom, kim o'chirgan, qachon, "Tiklash".

## Baza (RPC'lar)

- `public.audit_feed(p_from date, p_to date, p_table text default null, p_action text default null, p_actor uuid default null, p_device text default null, p_record_id uuid default null, p_before_id bigint default null, p_limit int default 50) returns table(id bigint, created_at timestamptz, table_name text, record_id uuid, action text, actor_profile_id uuid, actor_name text, device text, changed_fields text[], old_data jsonb, new_data jsonb, record_label text)` — `security invoker` (audit_log RLS), keyset sahifalash (`id < p_before_id`), `p_limit` ≤ 200, davr ≤ 366 kun.
- `record_label` — `private.audit_record_label(table_name, record_id, new_data, old_data)`: jadval bo'yicha qisqa nom (material nomi; harakat — "material · miqdor birlik tur"; xarid — "material · summa"; profil — ism; obyekt — nom; ...) — **faqat chaqiruvchi ko'ra oladigan** ma'lumotdan (`data` ichidagi qiymatlar + RLS bo'yicha join'lar), boshqa firma ma'lumoti yo'q.
- `public.deleted_records(p_from date, p_to date, p_table text default null, p_limit int default 100, p_offset int default 0) returns table(table_name text, record_id uuid, record_label text, deleted_at timestamptz, deleted_by_name text)` — invoker; oq ro'yxatdagi jadvallar.
- `public.restore_record(p_table text, p_id uuid) returns void` — `security invoker` (admin RLS va Batch 1 "tiklash faqat admin" triggeri amal qiladi), oq ro'yxat (biznes jadvallari; `audit_log`, `notification_outbox`, `alerts` emas), `update ... set deleted_at = null` dinamik SQL — **faqat** `format('%I', ...)` va oq ro'yxat orqali; mavjud triggerlar (birlik/material to'qnashuvlari, smeta joriylik, alias kaskadi) xato bersa — o'sha hint bilan qaytadi. Hint'lar: `restore_table_invalid`, `restore_not_found`, `restore_not_deleted`.
- Indekslar: `audit_log (company_id, id desc)`, `(company_id, table_name, record_id, id desc)`, `(company_id, actor_profile_id, id desc)`.

### Amalga oshirildi — `20261103000001_history.sql`

- Hammasi `security invoker`, `search_path = ''`, execute — faqat `authenticated` (anon/public — yo'q). `audit_feed`, `deleted_records`, `audit_record_label` — `stable`; `restore_record` — `volatile`.
- **Oq ro'yxat** (`private.history_tables()`, tiklash va "O'chirilganlar" uchun bir xil, 16 jadval): `profiles`, `objects`, `object_members`, `materials`, `material_units`, `material_aliases`, `suppliers`, `cash_advances`, `purchases`, `movements`, `material_requests`, `inventory_counts`, `inventory_count_items`, `estimates`, `estimate_items`, `estimate_import_templates`. **Kirmaydi:** `companies` (firma holati — faqat super_admin), `transfers` (**o'tkazma bekor qilinadi, tiklanmaydi** — faqat RPC, to'g'ridan-to'g'ri o'zgartirish `transfer_direct_edit` bilan bloklangan), `alerts`, `audit_log`, `notification_outbox`.
- **O'tkazma harakatlari** (`movements.transfer_id is not null`: `transfer_out`/`transfer_in`) — "O'chirilganlar"da chiqmaydi, tiklash → `restore_transfer_movement` (bekor qilingan o'tkazmaning harakati tiklansa qoldiq o'tkazma holatiga zid bo'lardi).
- `audit_feed`: davr — `private.report_period` (Batch 9: `p_to - p_from ≤ 365`, xato `report_period_invalid`), Toshkent kunlari bo'yicha `created_at`. `p_limit` 1..200, aks holda `history_limit_invalid`. `actor_name` — `profiles` (RLS) bo'yicha. RLS: admin, direktor — o'z firmasi; super_admin — hammasi; boshqa rollar — 0 qator. **Samaradorlik (O4):** so'rov dinamik SQL (`return query execute ... using`, qiymatlar faqat parametr) — faqat berilgan filtrlar qo'shiladi va har chaqiruv haqiqiy qiymatlar bilan rejalashtiriladi; super_admin bo'lmasa aniq firma sharti `company_id >= $co and company_id <= $co` + `order by company_id, id desc` (`=` bo'lsa planner firma kalitini tartibdan chiqarib, `audit_log_pkey` bo'ylab orqaga skanerlashni tanlashi mumkin — boshqa firmaning yangi qatorlari filtr bilan o'tkaziladi). EXPLAIN (PGlite, 2 firma × 20 000 qator): firma bo'yicha — `audit_log_company_id_idx`, yozuv bo'yicha — `audit_log_company_record_id_idx (company_id, record_id, id desc)`.
- `record_label` formatlari: material — nom; birlik — "Material · qop (variant)"; alias — "Цемент → Material"; a'zolik — "Ism · Obyekt"; harakat — "Material · 30 qop kirim" (`chiqim`, `o'tkazma (chiqdi)`, `o'tkazma (keldi)`, `inventarizatsiya tuzatishi`); xarid — "Material · 600 000 so'm · Sotuvchi"; podotchet — "Ism · 1 000 000 so'm"; o'tkazma — "Material · 1 kg · Obj1 → Obj2"; so'rov — "Material · 2 qop · Obyekt"; inventarizatsiya — "Inventarizatsiya · Obyekt"; uning qatori — "Material · 5 kg"; smeta — "Obyekt · Sarlavha · v1"; smeta qatori, shablon, obyekt, sotuvchi, firma — nom; profil va `auth` hodisasi — ism; alert — "tur · Obyekt · Material". Son: ortiqcha nollarsiz, kasr — vergul; summa — minglik probel. Yozuv firmasi chaqiruvchiga ochiq bo'lmasa (`can_access_company`) — `null`; nomlar join'i `company_id` bo'yicha ham cheklangan (begona id — nom chiqmaydi).
- `deleted_records`: faqat admin, direktor, super_admin (boshqalar — bo'sh, garchi RLS prorabga o'z o'chirilgan harakatlarini ko'rsatsa ham). `deleted_at` davrda; tartib `deleted_at desc, table_name, record_id`; `p_limit` 1..200, `p_offset ≥ 0` (`history_limit_invalid`); oq ro'yxatda yo'q `p_table` → `restore_table_invalid`. `deleted_by_name` — `audit_log` dagi oxirgi `SOFT_DELETE` aktyori. `inventory_count_items` uchun yorliq faqat ochiq ustunlardan (`qty_expected` yashirin).
- `restore_record` tartibi: (1) rol — admin/super_admin, aks holda `restore_admin_only`; (2) oq ro'yxat — `restore_table_invalid` (SQL injection urinishlari, qo'shtirnoqli/katta harfli/sxemali nomlar ham); (3) o'tkazma harakati — `restore_transfer_movement`; (4) `execute format('update public.%I set deleted_at = null where id = $1 and deleted_at is not null', p_table) using p_id`; **smeta (P1):** obyektda boshqa joriy versiya bo'lsa — yozuv `is_current = false` bilan tiklanadi (smeta RPC GUC'i ichida), xato emas; (5) 0 qator: ko'rinadigan va o'chirilmagan — `restore_not_deleted`, aks holda (yo'q, boshqa firma, RLS) — `restore_not_found`. Mavjud triggerlar o'z hint'i bilan: `catalog_name_duplicate`, `catalog_alias_duplicate` (alias va material kaskadi), `catalog_name_alias_conflict`, `catalog_unit_duplicate`, `catalog_material_deleted`, `inventory_locked` (yuborilgan inventarizatsiya qatori), `purchase_not_open` (**O1:** bog'langan xarid o'chirilgan kirim yoki so'rovni tiklash — `tg_compute_qty` / `tg_material_requests_guard` tiklashda ham tekshiradi), `cash_recipient_role` (podotchet oluvchisi nofaol/o'chirilgan) va h.k. (`estimate_restore_conflict` endi `restore_record` orqali chiqmaydi — faqat to'g'ridan-to'g'ri UPDATE'da.) Hint'siz `unique_violation` (profil telefoni, a'zolik, smeta versiyasi) → `restore_conflict` ("Tiklab bo'lmaydi: bir xil qiymatli faol yozuv bor"). Audit'da `RESTORE` yoziladi (a_before_update + z_audit).
- **Profil tiklanishi (O2)** — `b_profiles_restore_unlink` (before update, faqat `deleted_at` null ga qaytganda, hamma uchun — service_role ham): `auth_user_id`, `telegram_user_id`, `telegram_chat_id` → null, `login_kind = 'none'`, `is_active = false`. - **Tiklash signali (O3)** — alert turi `yozuv_tiklandi` (`purchases`, `cash_advances`, `movements` tiklanganda; `tg_soft_delete_alert` ichida; `zz_notify` — darhol bot). `yozuv_ochirildi` avvalgidek `closed_reason = 'restored'` bilan yopiladi. `severity`: o'chirilganidan beri ≥ 7 kun **yoki** yozuv sanasi (`occurred_at`/`purchased_at`/`issued_at`, Toshkent) joriy oydan oldin → `jiddiy` ("o'tgan davrni o'zgartirish"), aks holda `ogohlantirish`.
